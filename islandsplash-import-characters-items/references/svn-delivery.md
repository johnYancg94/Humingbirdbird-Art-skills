# SVN 资源交付

## 确定提交范围

- 以本次实际 Unity 工程和 SVN working-copy 根为准，核对每个目标文件的状态、冲突和 diff。结合修复前备份识别已有用户改动，记录本次增量。
- 首选 SVN 状态及差异工具。CLI 缺失时使用 TortoiseSVN；必要时只读 wc.db 和 pristine 辅助核对校验和，数据库内容保持只读，SVN 属性、换行转换和混合修订需通过客户端复核。
- 修复沿用原资产路径与 .meta/GUID，只纳入实际产生差异的依赖。曾有厨师企鹅修复最终只需提交一个 .anim，模型、prefab 和 .meta 均无需随动画重复提交。每次以当前状态重新确认。
- 备份、截图、验证报告、候选文件和临时脚本存放 Assets 外，提交清单限定本次正式资源。逐项检查 Fix 目录或临时 enhanced 动画是否仍有引用，修复引用并确认可恢复后清理。
- 冲突文件的内容修复和 SVN 的 resolved 状态分别检查。报告仍有冲突的路径及原因，按授权处理，再刷新清单。

## 路径清单编码

先生成规范化路径数组，再显式序列化。每个条目验证目标存在、属于指定 working copy、无重复、无尾随 CR、无 BOM 混入首条路径。

- 通用可读清单使用 UTF-8 无 BOM、纯 LF。
- 本环境已验证的 TortoiseProc /pathfile 使用 Windows 反斜杠绝对路径、UTF-16LE 无 BOM、纯 LF。最终以客户端加载的路径和条目数验收。
- 提交说明使用 UTF-8 无 BOM、纯 LF，写清问题、修复范围和实际验证结果。
- 以字符串 `"\n".join(paths) + "\n"` 构造内容，再用 write_bytes(text.encode(...)) 写入。避免平台默认 CRLF 转换。
- 回读时按对应编码解码后检查 `"\r" not in text` 和 `"\ufeff" not in text`。UTF-16 的字节级零值属于编码本身，检查 CR 应针对解码文本。

## 审核窗口与提交权限

用户要求准备或更新窗口时，通过已验证的路径文件和 logmsgfile 打开 TortoiseSVN Commit，核对勾选数量、文件状态及提交说明。用户保留最终确认提交时，将窗口交付给用户操作。用户明确授权正式提交时，按该授权执行，并以客户端成功结果与修订号报告完成。
